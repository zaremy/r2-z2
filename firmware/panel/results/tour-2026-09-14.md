# The panel on glass, all nine views — 2026-09-14

**First on-hardware look at anything merged since #155.** Five PRs of UI had
shipped without a single frame from the device: the fault chain, the wake
frame's machinery, the bounded `waking`, the SERVICE menu and its seven
interiors. This is the run that ended that.

Captured by the tour build (#164) in one boot:

```
idf.py -B build-tour -DPANEL_SHOT_TOUR=ON build flash
tools/grab_tour.sh /dev/cu.usbmodem101 tour build-tour
```

Firmware `d1d3a50`, R2 linked throughout. Nine slots, captures #1 to #9, all
present — so every tap opened the interior it aimed at. A tap that missed
would have left its slot erased and `grab_tour.sh` would have said NO FRAME.

## What the frames prove

| Frame | Reads |
|---|---|
| `tour-status` | IDLE, `NOTHING ENGAGED`, R2 PWR **4.42 V** on a green 18-bar gauge, DOME **009°** with the needle and its heading wedge drawn, page dots at the foot |
| `tour-service` | NETWORK / R2 LINK / DIAGNOSTICS / HARDWARE TEST, 87 px rows, `››` right-aligned, R2 LINK's square **green**, scrollbar present |
| `tour-r2-link` | STATE **LINKED** (green), CEILING **READ**, ANSWERED **3/3**, KEEPALIVE **3S**, LAST READ **1S AGO**, R2 FW `----` |
| `tour-diagnostics` | BOARD **S3 V2**, PANEL **CO5300**, TOUCH **CST820**, FLASH 16 MB, PSRAM 8 MB, FREE HEAP 7203 KB |
| `tour-hardware-test` | `CEIL READ`, READ **ALLOWED**, LEDS/AUDIO/DOME/STANCE/LOCOMOTION **LOCKED**, footer `EACH TIER OPT-IN · NEVER BUNDLED` |
| `tour-provisioning` | WI-FI and API KEY **NOT IN BUILD**, PAIRS WITH `FIRST D2-`, NVS **OK** |
| `tour-voice` | `ON THE MAC` / `NOT VISIBLE FROM HERE` |
| `tour-camera` | `NO CAMERA` / `NONE IN THIS BUILD` |
| `tour-about` | MODEL R2Z2, FW **D1D3A50**, BOARD S3 V2, UPTIME 0M 28S |

Four things that were argued for on paper and are now observed:

1. **The board-revision probe works.** TOUCH reads `CST820` — the chip
   answered 0xB7 at I2C 0x15 — so BOARD says V2 on evidence rather than
   because the build assumes it (`board-revision.md`'s probe, run at boot).
2. **The permission ladder is right at the real ceiling.** READ allowed,
   everything above it locked, all six rungs on screen, no bundled run-all.
3. **The hit test works with a scrolled list.** Rows 5-7 are below the fold
   and opened correctly, which is the case that was wrong in the tour's own
   first draft.
4. **Both typefaces render** at every size, including the chevrons and the
   middle dot in the ladder's footer.

## What this run does NOT prove

- **Nothing about touch hardware.** The tour enters below `panel_touch.c`, so
  the controller, the press and release edges, the tap-versus-scroll
  thresholds and the moving-list guard are all still unobserved. A finger is
  the only way to test those.
- **Nothing about `offline` or the wake frame.** R2 was linked for the whole
  run, so the states that draw the fault chain never occurred. To see them:
  switch R2 off with the panel running, or flash with him already off — the
  wake frame then fires about 5 s after boot and reads `NOT SEEN`.
- **Nothing about burn-in drift**: the whole tour finishes inside one 60 s
  drift step, so all nine frames share one alignment.

## Polish found by looking

Small, and none of it wrong — each is a thing that reads oddly rather than
falsely. Worth a follow-up:

1. **`PAIRS WITH  FIRST D2-`** reads like a truncated string. It means "the
   first advertiser whose name begins D2-", which is what `r2_link` does.
2. **`R2 FW ----`** is honest but permanently blank: nothing in this firmware
   ever requests his version, so the row can never fill. Either ask for it
   once per connect (it is a read-tier op, already allowed) or drop the row.
3. **The VOICE and CAMERA notes sit above centre** — about y=150 in a body
   that runs 76 to 448. The reference centres them in the space.
4. **`FREE HEAP 7203 KB`** counts PSRAM, so it reads high for something
   labelled heap.
